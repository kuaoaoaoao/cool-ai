## ADDED Requirements

### Requirement: 媒体任务工具调用
系统 SHALL 允许 AI 聊天通过已启用的 Tool 或 MCP 能力创建和查询媒体任务。

#### Scenario: 聊天创建 TTS 任务
- **WHEN** 用户在聊天中请求生成语音且聊天角色启用了 TTS 工具
- **THEN** 系统 SHALL 通过媒体任务服务创建 TTS 任务，并向聊天返回任务 ID 和查询方式

#### Scenario: 聊天查询任务状态
- **WHEN** 用户在聊天中询问媒体任务进度
- **THEN** 系统 SHALL 通过媒体任务服务查询任务状态并返回当前状态、进度和结果摘要

### Requirement: 工具权限和角色控制
系统 MUST 按聊天角色、用户权限和租户配置控制可调用的媒体工具。

#### Scenario: 角色未启用工具
- **WHEN** 聊天角色未绑定 TTS 或视频工具
- **THEN** 系统 MUST 不向模型暴露该媒体工具

#### Scenario: 用户无权限
- **WHEN** 用户没有创建某类媒体任务的权限
- **THEN** 系统 MUST 拒绝工具调用

### Requirement: 敏感工具二次确认
系统 MUST 对声音克隆、人物替换等敏感媒体工具执行二次确认流程。

#### Scenario: 敏感任务未确认
- **WHEN** AI 聊天准备创建声音克隆或人物替换任务但用户尚未确认
- **THEN** 系统 MUST 不创建任务，并要求用户明确确认

#### Scenario: 敏感任务已确认
- **WHEN** 用户明确确认并通过权限、素材归属和功能开关校验
- **THEN** 系统 SHALL 允许工具创建对应媒体任务

### Requirement: 配额和成本控制
系统 MUST 在聊天工具创建高成本媒体任务前执行用户或租户级配额校验。第一阶段 SHALL 采用最小配额控制，包括功能开关、权限校验和简单用户/租户使用限制。

#### Scenario: 配额不足
- **WHEN** 用户或租户配额不足
- **THEN** 系统 MUST 拒绝创建媒体任务，并返回配额不足提示

#### Scenario: 配额充足
- **WHEN** 用户或租户配额充足
- **THEN** 系统 SHALL 允许继续创建任务，并记录任务用于后续成本统计

#### Scenario: 第一阶段最小配额控制
- **WHEN** 聊天工具创建 TTS 任务
- **THEN** 系统 SHALL 至少校验功能开关、用户权限和简单使用限制，不要求实现完整计费系统

### Requirement: 工具调用审计
系统 SHALL 记录聊天触发的媒体任务审计信息，包括用户、租户、聊天会话、工具名称、任务 ID 和敏感操作确认信息。

#### Scenario: 聊天创建媒体任务
- **WHEN** 聊天工具成功创建媒体任务
- **THEN** 系统 SHALL 保存该工具调用和媒体任务之间的关联审计信息

#### Scenario: 敏感工具被拒绝
- **WHEN** 敏感工具调用因权限、确认或配额失败被拒绝
- **THEN** 系统 SHALL 记录拒绝原因用于后续审计

### Requirement: 工具不得绕过任务中心
系统 MUST 保证聊天工具通过媒体任务服务创建和查询任务，不得直接调用第三方 Provider 或 Python Worker。

#### Scenario: 创建工具任务
- **WHEN** 聊天工具需要生成音频或视频
- **THEN** 工具 MUST 调用媒体任务服务，由媒体任务服务选择 Provider 并管理状态

#### Scenario: 查询工具结果
- **WHEN** 聊天工具需要返回生成结果
- **THEN** 工具 MUST 从媒体任务服务读取任务结果，而不是直接读取 Provider 临时响应
